# デモ動画の参考映像の調査

書いた人：Taiga ／ 最終更新：2026-11-15（#206）

デモ動画を作るための参考として、2 本の映像の構成・カット割り・音を調べた。

| ファイル | 元の映像 | 尺 | 備考 |
|---|---|---|---|
| `deadline-delivery-trailer.mp4` | DEADLINE DELIVERY - Official Trailer（GOOD1 Studios） | 0:57 | 元のまま（21MB） |
| `splatoon-intro.mp4` | Splatoon（スプラトゥーン）紹介映像（Nintendo 公式チャンネル） | 6:41 | 71MB → 44MB に再圧縮（映像のみ。音は元のまま） |

どちらも他社の著作物。**参考として見るだけにし、私たちの動画に素材を使わない。リポジトリを公開する前に、この 2 本の mp4 は消す。**

## 先に結論：私たちのデモ動画に持ち帰ること

1. **最初の 5〜6 秒は UI もロゴも出さない。** DEADLINE DELIVERY は速度計 → 排気管 → 爆弾の荷物 → 運転手の顔、の寄りの絵 4 枚だけで「何のゲームか」を伝えてからプレイ画面に入る。私たちなら、計器盤の針 → 酸素タンクの警告灯 → 乗組員の顔 → 窓の外の月。
2. **売りは 1 枚 3〜4 語の文字カードで言い切り、プレイ映像の上に重ねる。** DEADLINE DELIVERY は 4 枚だけ（DELIVER THE MAIL ／ 18 MAPS ／ MULTIPLAYER UP TO 8 PLAYERS ／ LEADERBOARDS）。7〜8 秒に 1 枚。黒い画面で止めずに、走っている絵の上に斜めに出す。私たちなら「BRING THEM HOME」「4 SEATS, ONE SHIP」「REAL NASA ORBITS (GMAT)」「EVERY SECOND COSTS OXYGEN」あたりの 4 枚。
3. **失敗の絵を必ず入れる。** DEADLINE DELIVERY は 57 秒のうち爆発・DELIVERY FAILED を 4 回見せている。失敗が見えると緊張と笑いが伝わる。私たちは「電力か酸素が 0」のエンディングを 1 回は見せる。
4. **長く説明するなら章に分け、章の名前を画面の隅に出し続ける。** Splatoon は 6 分 41 秒を 8 章に分け、章の頭に 2〜3 秒の 1 枚絵カード、章の間は左上に章名のラベル、右下に今見せている物の名前を出している。途中から見ても今どこか分かる。私たちが 4 席（役割）を紹介するなら、席ごとに色を変えたカード＋隅のラベルにする。
5. **終わりの形は「山場の連打 → ロゴ → 日付や名前 → 作った人」。** 2 本とも同じ。DEADLINE DELIVERY は最後の 10 秒をロゴ（3 秒）→ キーアート＋発売日（4 秒）→ スタジオロゴ（3 秒）に使う。私たちは ロゴ → チーム名「遠慮のNASA」＋ NASA Space Apps 2026 → 使った NASA のデータ。
6. **音は曲 1 本を頭から鳴らし、無音を作らない。カットに効果音を当てると差が出る。** DEADLINE DELIVERY は開始 0.04 秒で音が鳴り、無音の区間がない。一方、カットの 3 分の 2 に音のアクセントがなく、earshot の採点で一番減点された。ここは真似せず、文字カードが出る瞬間と事故の瞬間にヒット音やウーシュを当てる。

## DEADLINE DELIVERY トレーラー（57 秒）

協力・競争型の配達レースゲームの発売告知。短い告知動画の型として、そのまま使える。

### 構成

| 時間 | 中身 | 画面の文字 |
|---|---|---|
| 0:00–0:06 | 導入。速度計、排気管、爆弾の荷物、運転手（猿）の寄り。上下に黒帯、UI なし | なし |
| 0:07–0:11 | プレイ映像。高速で走る、運転席の視点 | なし（ゲーム内のタイマーと速度だけ） |
| 0:12–0:18 | 目的の提示。走る → 崖から落ちて失敗 → 橋 | **DELIVER THE MAIL** |
| 0:19–0:24 | 量の提示。違うマップを 1 秒ずつ 5 枚 → DELIVERY FAILED | **18 MAPS** |
| 0:25–0:26 | ガレージ（車の着せ替え）の画面を 2 秒 | なし |
| 0:27–0:33 | 多人数。複数の車が並んで走る、トンネル、衝突 | **MULTIPLAYER UP TO 8 PLAYERS** |
| 0:34–0:38 | ランキング。走り → ランキング画面で自分の行が 1 位に上がる | **LEADERBOARDS** |
| 0:39–0:46 | 山場。爆発 2 回、運転席の視点で橋を渡る | なし |
| 0:47–0:49 | ロゴ（黒地） | DEADLINE DELIVERY |
| 0:50–0:53 | キーアート＋発売日 | MARCH 16 |
| 0:54–0:57 | スタジオロゴ（黒地） | good1 studios |

### 絵の作り

- 画面が変わる回数は 57 秒で 51 回（earshot の検出。約 1.1 秒に 1 回）。はっきりしたカットは 16 回。
- 文字カードは白い太字に黒い影、斜めに傾けて画面の左か中央に大きく。出ている時間は約 1 秒。
- メニュー画面（ガレージ、ランキング）は合わせて 4 秒だけ。ほぼ全部が「動いているプレイ映像」。
- ゲーム内の UI（タイマー、速度）は消さずに見せている。本物のプレイだと分かる。

### 音（earshot）

総合：プロの告知映像 7 本の基準に対し、23 項目中 19 項目が範囲内（82%）。

| 項目 | 値 | 読み方 |
|---|---|---|
| 音量（integrated） | -14.1 LUFS | Web 動画の標準どおり。私たちも -14 LUFS 前後に合わせる |
| 最大ピーク | -2.4 dBTP | 割れていない |
| 音楽が鳴っている割合 | 83% | ほぼ全編が曲。声・ナレーションは 0% |
| テンポ | 144 BPM | 基準（115〜136）より速い。急ぐゲームの内容に合わせている |
| 最初の音まで | 0.04 秒 | 頭から鳴る |
| 途中の無音 | 最長 0.02 秒 | 無音なし |
| 一番大きい 3 秒の位置 | 全体の 81% | 山場（0:40〜0:46）が一番大きい |
| 終わり | 2.6 秒かけて消える | 最後の 10% は -7.8 LU まで下げ、ロゴを静かに見せる |
| 音の立ち上がり | 1.3 回/秒（基準 2.2〜8.5） | 少ない。曲任せで効果音が薄い |
| 画面の変化に音が合う割合 | 33%（基準 45% 以上） | 51 回中 34 回はアクセントなし |
| 目立つヒット音 | 0 回/秒 | なし |

弱いところ（＝私たちが上回れるところ）：カットや文字カードに合わせた効果音がない。0:40 の一番大きい画面の変化の直前に、0.2〜1 秒だけ音を止めてから鳴らす手（基準の 7 本中 4 本が使う）も使っていない。

## Splatoon 紹介映像（6 分 41 秒）

発売前に、ゲームの全部を順に説明する映像。長い説明をどう飽きさせずに見せるかの参考になる。

### 構成

| 時間（約） | 章 | 中身 |
|---|---|---|
| 0:00–0:18 | 導入 | Wii U ロゴ → 説明なしのプレイ映像を 3 秒ずつ 5 枚 → タイトルロゴ |
| 0:18–0:54 | 主人公は…イカ!? | 基本の動き（塗る、潜る、変身）を 1 つずつ |
| 0:54–1:57 | ナワバリバトル | 4 対 4 の対戦の流れ、Wii U GamePad の地図、ほかのルール（ガチエリア、ガチヤグラ） |
| 1:57–2:33 | フェス／ステージ | 催しと、ステージ 5 つを名前付きで 3 秒ずつ |
| 2:33–3:24 | ブキ | 武器の種類ごとに名前のラベル付きで |
| 3:24–4:09 | ハイカラシティ | 街、店、装備の画面 |
| 4:09–4:54 | ヒーローモード | 1 人用の冒険、ボス |
| 4:54–5:12 | バトルドージョー | 2 人対戦 |
| 5:12–5:36 | アップデート | 発売後に増えるもの |
| 5:36–6:00 | 山場 | 全部の章から早いカットの連打（30 秒で 18 カット。全体で一番速い） |
| 6:00–6:06 | 締め | タイトルロゴ＋発売日＋価格 |
| 6:06–6:41 | おまけ | amiibo の紹介 → 商品と発売日 |

### 絵の作り

- カットは 400 秒で 162 回（平均 2.5 秒に 1 回）。導入の 30 秒（21 回）と山場の 30 秒（18 回）が速く、説明の章は 30 秒に 10〜15 回、メニュー画面を見せる章（3:30〜4:00）は 4 回まで落とす。**速い → ゆっくり → 速い**の波がある。
- 章の頭のカードは、インクのしぶき＋キャラクターの 1 枚絵＋章名の太い文字。章ごとに色が違う（橙、紫、水色、黄緑、青、桃）。2〜3 秒。
- 章の間は、左上に章名のラベルが出続ける。右下には今見せている物の名前（ステージ名、武器名、ルール名）が丸いラベルで出る。
- 1 つの物を見せる時間は約 3 秒で固定。ステージ 5 つ、武器 4 種を同じ長さで並べるので、リズムが揃う。
- ロゴと発売日の後に、別の話題（amiibo）を 35 秒足している。本編の締めを先に済ませてあるので、ここで見るのをやめても伝わる。

### 音（earshot）

総合：プロの告知映像 7 本の基準に対し、23 項目中 16 項目が範囲内（71%）。基準は 1 分前後の告知映像なので、ナレーション中心の長い説明映像は点が低く出る。数字は「告知との作りの違い」として読む。

| 項目 | 値 | 読み方 |
|---|---|---|
| 声が入っている割合 | 62% | ナレーションが主役。DEADLINE DELIVERY（0%）と正反対 |
| 音楽が鳴っている割合 | 99% | ナレーションの下でも曲は止めない |
| テンポ | 120 BPM | 基準の範囲内。説明を聞かせる速さ |
| 音量（integrated） | -17.4 LUFS | Web の標準（-14）より 3.4 dB 小さい。声を聞かせるため全体が控えめ |
| 音量の幅 | 4.8 LU | 章が変わってもほぼ一定。聞き疲れしない |
| 目立つヒット音 | 0.95 回/秒 | 多い。インクの発射音などゲームの効果音がそのまま鳴っている（DEADLINE DELIVERY は 0） |
| 音を一瞬止める回数 | 1.3 回/分 | 章の切り替えで使っている |
| 一番大きい 3 秒の位置 | 全体の 86% | 山場（5:36〜6:00）が一番大きい。DEADLINE DELIVERY（81%）と同じ形 |
| 画面の変化に音が合う割合 | 21%（基準 45% 以上） | カットは音に合わせていない。ナレーションの文に合わせて切っている |
| 低音（20〜60 Hz） | -26.5 dB（基準 -17.7 以上） | 低音が薄い。声とゲーム音の帯域（1〜8 kHz）が厚い |

読み取れること：説明する動画では、曲は 120 BPM 前後で音量を一定にし、声の邪魔をしない。迫力はゲーム内の効果音で出す。一番大きい音は 2 本とも全体の 8 割を過ぎたところに置いている。

## 解析データ（`analysis/`）

| ファイル | 中身 | 作り方 |
|---|---|---|
| `*.critique.json` / `.txt` | 音の採点（音量、ピーク、立ち上がりの密度、カットとの同期、周波数、ステレオ幅など） | `earshot critique <動画> --out <json>` |
| `*.timeline.json` / `.txt` | 音の出来事を時刻順に並べたもの | `earshot timeline <動画> --detail high --out <json>` |
| `*.describe.json` / `.txt` | 音全体の特徴とタグ | `earshot describe <動画> --out <json>` |
| `*.sheet.png` | 波形・コマ・カットを 1 枚にまとめた図 | `earshot sheet <動画> -o <png> --width 2400` |
| `*.cuts.txt` | カットの時刻（秒） | `ffmpeg -vf "select='gt(scene,0.3)',showinfo"` |
| `*.frames-NN.jpg` | コマの一覧。DEADLINE DELIVERY は 1 秒ごと、Splatoon は 3 秒ごと。左上から右へ | `ffmpeg -vf "fps=1/N,scale=320:180,tile=6xR"` |

道具：[earshot](https://github.com/Leonxlnx/earshot)（MIT。音声モデル 2 つを Hugging Face から取得し、すべて手元で動く）、ffmpeg 9.0.2。
